Scenario
A university currently receives student requests for services such as ID card replacement, transcript
requests, and certificate requests through manual forms and email. This makes it difficult for students to
track their requests and for university staff to manage them efficiently.
The university wants a simple Student Service Request System developed using ASP.NET MVC.
The system should allow students to submit a service request and check its status. A staff member should
be able to view submitted requests and update their status.
However, the university has two important concerns:
• The system should be simple and easy to use for students.
• Only authorized staff should be able to access and modify student requests.
You are required to analyze the problem, propose a suitable solution, and develop a functional
ASP.NET MVC application.
Tasks
Part A — Problem Analysis
Analyze the given problem and:
1. Identify the main users/stakeholders of the system.
2. Identify the major functional requirements of the system.
3. Identify the major non-functional requirements.
4. Identify the conflict between ease of use and access control/security.
5. Explain how this conflict should influence your system design.

Part B — System Design
Based on your analysis, design the proposed solution.
Your design should include:
• The main Models required.
• The main Controllers required.
• The main Views required.
• A simple database structure.
• A basic diagram showing how the User → View → Controller → Model/Database components
interact.
You should briefly justify why your proposed structure is appropriate for the problem.
Part C — ASP.NET MVC Implementation
Develop a functional prototype with the following minimum features:
Student
A student should be able to:
• Register/login to the system.
• Submit a service request.
• Select a request type, such as:
o ID Card Replacement
o Transcript Request
o Certificate Request
• Provide a short description of the request.
• View their submitted requests.
• View the status of each request.
Staff
A staff user should be able to:
• Login to the system.
• View submitted service requests.
• View the details of a request.
• Change the request status to:
o Pending
o Processing
o Completed
o Rejected
